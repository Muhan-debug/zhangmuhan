## 一、工具篇：搭好你的"手术台"

> 外科医生上台前要铺好无菌巾、摆好器械。做 AI 实验也一样——**环境没配好，后面的一切都是空谈**。

### 1.1 Python 环境配置：从零开始不恐慌

这一节你只需要安装两个软件：**Anaconda**（管理 Python 环境）和 **VS Code**（写代码的编辑器），跟着步骤一步一步来。

------

#### 第一部分：安装 Anaconda

1. 打开浏览器，访问 Anaconda 官网：**https://www.anaconda.com/**

   > ⚠️ 如果网页打不开或下载很慢，请先搭建梯子（方法后续讲解）后再操作。

2. 点击页面上的下载按钮，选择适合你系统的版本（Windows 选 `.exe`，Mac 选 `.pkg`）。

3. 下载完成后，双击安装包开始安装。安装过程按默认推荐选项点击"Next"即可，**但有一点必须注意**：

   > ⚠️ **安装路径必须全为英文字母！** 不能有中文、空格或特殊符号。例如 `D:\anaconda3` 是安全的，`D:\我的软件\anaconda` 会导致后续报错。

4. 安装过程需要等待较长时间（5～15 分钟），耐心等待进度条走完即可。

5. 安装完成后，在 Windows 开始菜单中搜索 **"Anaconda Prompt"**，能打开一个黑色命令窗口说明安装成功。

   > 📹 **参考视频**：如果以上步骤有不理解的地方，可参考 B 站教程（搜索"Anaconda安装教程 2024"），看到安装软件部分即可，**C++ 相关步骤无需操作**。

------

#### 第二部分：安装并配置 VS Code

VS Code 是目前最流行的代码编辑器，界面友好，新手友好。

1. 访问 VS Code 官网下载安装包：**https://code.visualstudio.com/**，按默认选项安装完成。
2. **汉化界面**（强烈推荐）：
   1. 打开 VS Code，点击左侧边栏第四个图标（四个小方块，即"扩展"按钮）。
   2. 在搜索框中输入 `chinese`。
   3. 找到 **"Chinese (Simplified)"** 插件，点击 **Install（安装）**。
   4. 安装完成后重启，界面变为中文即成功。
3. **安装 Python 插件**：
   1. 同样在扩展搜索框中输入 `python`。
   2. 安装微软官方出品的 **Python** 插件（图标为蓝色蟒蛇）。

------

#### 第三部分：让 VS Code 找到 Anaconda 的 Python

> 💡 **为什么要特意指定 Anaconda 里的 `python.exe`？**
>
> 你的电脑上可能已经有一个"系统自带的 Python"，但它和 Anaconda 的环境是完全割裂的——你在 Anaconda 里安装的所有科研包（`pandas`、`transformers` 等），系统 Python 根本找不到。**不指定正确的解释器，代码永远都会报"找不到包"的错误。**

操作步骤如下：

1. 在 VS Code 中按下快捷键 **`Ctrl + Shift + P`**，顶部会出现一个命令搜索框。
2. 输入 `Python: Select Interpreter`（输入前几个字母会自动补全），按回车。
3. 在弹出的列表中，找到路径中包含 **`anaconda`** 字样的那一个，例如：

```
   Python 3.x.x ('base': conda)  ~/anaconda3/bin/python
```

点击选择它。

> ⚠️ 如果列表中没有出现 Anaconda 的选项，点击 **"Enter interpreter path..."**，手动粘贴 Anaconda 的 `python.exe` 路径。Windows 用户的路径通常类似于 `C:\Users\你的用户名\anaconda3\python.exe`。

2. 在下方的终端面板中，看到输出即意味着配置完成：

```

#### 第二步：安装所需的 Python 库

------

#### 第三步：写你的第一个 API 调用代码

新建一个文件，命名为 `qwen_test.py`，将以下代码完整复制进去：

python

```python
from openai import OpenAI

# =============================================
# 【通行证】API Key：进入实验室的身份凭证
# 就像你的工牌——证明你是有权限调用模型的用户
# 请将引号内替换为你自己的 API Key
# =============================================
client = OpenAI(
    api_key="sk-xxxxxxxxxxxxxxxxxxxxxxxx",  # 替换为你的 API Key
    base_url="https://dashscope.aliyuncs.com/compatible-mode/v1"  # 阿里云百炼的接口地址
)

# =============================================
# 【会诊申请】构造发送给模型的消息
# messages 就像一份会诊单，告诉模型它的角色和你的问题
# =============================================
response = client.chat.completions.create(
    # 【科室选择】model：决定调用哪个"专科医生"（模型版本）
    # qwen-plus 性价比高，适合日常任务；qwen-max 能力更强但消耗 Token 更多
    model="qwen-plus",

    messages=[
        {
            # system：给模型设定角色，相当于告诉会诊医生"你是心内科专家"
            "role": "system",
            "content": "你是一位专业的医疗信息提取助手，擅长从中文病历中提取结构化信息。"
        },
        {
            # user：你真正想问的问题，相当于会诊单上的"会诊目的"
            "role": "user",
            "content": (
                "请从以下病历片段中，提取"主诉"、"诊断"两项信息，"
                "以 JSON 格式输出。\n\n"
                "【病历】患者，男，72岁，因'反复胸闷、气促5年，加重伴双下肢水肿1周'入院。"
                "既往高血压病史20年。入院诊断：慢性心力衰竭急性加重期。"
            )
        }
    ]
)

# =============================================
# 【读取报告】提取模型返回的文字内容
# =============================================
result = response.choices[0].message.content
print(result)
```

运行后，你应该会看到类似下面的输出：

json

```json
{
  "主诉": "反复胸闷、气促5年，加重伴双下肢水肿1周",
  "诊断": "慢性心力衰竭急性加重期"
}
```

至此你已经完成了第一次大模型 API 调用。

#### ⚠️ 避坑 Tips：API Key 安全须知

请务必遵守以下原则：

1. **绝对不要上传到 GitHub 等公开仓库。** GitHub 会自动扫描并警告 API Key 泄露。一旦泄露，他人可以用你的额度无限调用，产生的费用由你承担。
2. **使用环境变量存储，而非硬编码在代码里。** 正确做法：

python

```python
   import os

   # 从系统环境变量中读取 API Key，而非直接写在代码里
   api_key = os.environ.get("DASHSCOPE_API_KEY")
   client = OpenAI(api_key=api_key, base_url="https://dashscope.aliyuncs.com/compatible-mode/v1")
```

在终端中设置环境变量（每次开新终端需重新设置，或写入系统配置文件）：

bash

```bash
   # Windows（Anaconda Prompt）
   set DASHSCOPE_API_KEY=sk-xxxxxxxxxxxxxxxxxxxxxxxx

   # Mac / Linux
   export DASHSCOPE_API_KEY=sk-xxxxxxxxxxxxxxxxxxxxxxxx
```

------

#### Token 用量小贴士

调用 API 是按 **Token**（可以粗略理解为"字数"）计费的。在免费额度期间，注意以下几点可以节省用量：

- `system` 提示词尽量简洁，不要长篇大论
- 不需要历史对话时，每次调用都重新构建 `messages`，不要无限累积上下文
- 上传文件时先压缩删除无效间隔与空白段落等

## 二、实战篇：让 AI 成为你的编程搭档

> 报错不是失败的信号，真正的差距不在于你会不会写代码，而在于你会不会向 AI 提问。 本章教你掌握与 AI 协作 Debug 的方法论。

------

### 2.1 Debug 方法论：为什么你的提问没有得到好答案

很多人遇到报错后，第一反应是把错误信息单独截图发给 AI，然后问："为什么它给不出有用的答案？"

**原因很简单：你给 AI 的信息，远不足以让它做出准确判断。**

> 💡 **医学类比**：想象一位急诊科医生只收到一句话——"病人很不舒服"——他能开出正确的处方吗？他需要的是：主诉、现病史、体征、检查结果……AI 也一样，它需要的是完整的"病历"，而不是一句"我的代码报错了"。

#### AI Debug 需要你提供

**一：代码上下文（不是只发报错那一行）**

报错的那行代码往往只是"症状"，真正的"病因"可能在十行之前的变量定义里。**必须提供完整的、可复现问题的代码片段**，而非单行截图。

**二：完整的错误追溯（Traceback）**

Traceback 是系统给出的错误调用链，每一行都是线索。很多人只复制最后一行红色文字，丢失了最关键的文件路径和行号信息。**请完整复制从 `Traceback (most recent call last):` 开始的全部内容。**

**三：数据样本（哪怕只有几行）**

尤其是处理临床数据集时，同样的代码在不同数据上可能有完全不同的表现。**提供 3～5 行真实（或脱敏后的）数据样本**，让 AI 能理解你的数据结构，而不是凭空猜测。

------

### 2.2 三个核心技巧：

#### 技巧一：给 AI 设定专业身份（角色设定）

在对话开始时，用一句话告诉 AI 它是谁、你是谁、任务是什么。

没有角色设定的提问，AI 会给出泛化的通用答案；有了角色设定，它会用更专业、更贴合你场景的语言来回应。

> **不带角色设定（泛化）：** "帮我修这段 Python 代码"

yes_no_map = {"Yes": 1, "No": 0}
X[string_cols] = X[string_cols].replace(yes_no_map)

assert X.select_dtypes(include="object").empty, "仍有未处理的字符串列！"

# 现在可以安全训练
model = RandomForestClassifier(n_estimators=100, random_state=42)

### 2.6 实战案例补充：病历实体抽取中的 JSON 解析问题

**背景**：在挑战一（中文病历实体抽取）中，调用大模型 API 并要求返回 JSON 格式结果，但模型经常在 JSON 外面包裹 Markdown 代码块，导致直接解析失败。

**报错现象**：

python

```python
import json

response_text = response.choices[0].message.content
# 模型实际返回的内容长这样：
# ```json
# {"疾病": ["高血压", "心力衰竭"], "症状": ["心悸", "气促"]}
# ```

result = json.loads(response_text)  # 报错！
json.JSONDecodeError: Expecting value: line 1 column 1 (char 0)
```

**根本原因**：模型"礼貌性"地用 Markdown 代码块包裹了 JSON，但 `json.loads()` 只能解析纯 JSON 字符串，无法处理 ````json` 这样的格式符号。

**修复方案**：

python

```python
import re
import json

def safe_parse_json(text: str) -> dict:
    """
    安全解析大模型返回的 JSON 字符串。
    
    改动原因：
    - re.sub 用于剥离模型可能添加的 Markdown 代码块标记
    - try/except 确保解析失败时不会让整个程序崩溃
    - 返回空字典而非抛出异常，便于后续逻辑继续处理
    """
    # 去除 ```json ... ``` 或 ``` ... ``` 包裹
    text = re.sub(r"```(?:json)?\s*", "", text).strip()
    text = text.replace("```", "").strip()

    try:
        return json.loads(text)
    except json.JSONDecodeError as e:
        print(f"⚠️ JSON 解析失败，原始内容：\n{text}\n错误信息：{e}")
        return {}

# 使用示例
result = safe_parse_json(response_text)
print(result)
# 输出：{"疾病": ["高血压", "心力衰竭"], "症状": ["心悸", "气促"]}
```

import matplotlib.pyplot as plt
from sklearn.datasets import make_classification
from sklearn.model_selection import train_test_split
from sklearn.ensemble import RandomForestClassifier, GradientBoostingClassifier
from sklearn.linear_model import LogisticRegression
from sklearn.metrics import roc_curve, auc

# ── 生成心衰模拟数据 ──────────────────────────────────
X, y = make_classification(n_samples=300, n_features=12,
                            random_state=42)
X_train, X_test, y_train, y_test = train_test_split(
    X, y, test_size=0.3, random_state=42)

# ── 训练三个模型 ───────────────────────────────────────
models = {
    "Random Forest": RandomForestClassifier(n_estimators=100, random_state=42),
    "XGBoost":       GradientBoostingClassifier(random_state=42),
    "Logistic Reg.": LogisticRegression(max_iter=1000)
}
colors = ["#1f77b4", "#ff7f0e", "#2ca02c"]  # 色盲友好配色

# ── 绘图 ───────────────────────────────────────────────
fig, ax = plt.subplots(figsize=(6, 5), dpi=300)

for (name, model), color in zip(models.items(), colors):
    model.fit(X_train, y_train)
    y_score = model.predict_proba(X_test)[:, 1]
    fpr, tpr, _ = roc_curve(y_test, y_score)
    roc_auc = auc(fpr, tpr)
    # 在图例中直接标注 AUC 值
    ax.plot(fpr, tpr, color=color, lw=2,
            label=f"{name} (AUC = {roc_auc:.3f})")

# 随机猜测基准线（灰色虚线）
ax.plot([0, 1], [0, 1], color="gray", lw=1.5,
        linestyle="--", label="Random Guess")

ax.set_xlim([0.0, 1.0])
ax.set_ylim([0.0, 1.05])
ax.set_xlabel("False Positive Rate", fontsize=12)
ax.set_ylabel("True Positive Rate", fontsize=12)
ax.set_title("ROC Curves – Heart Failure Prediction", fontsize=13)
ax.legend(loc="lower right", fontsize=10)
ax.spines[["top", "right"]].set_visible(False)  # 去掉多余边框

plt.tight_layout()
plt.savefig("roc_curve.png", dpi=300, bbox_inches="tight")
plt.show()
print("✅ 图片已保存为 roc_curve.png")
```

#### 图表三：特征重要性条形图

用随机森林或 XGBoost 训练完模型后，特征重要性图能直观展示"哪些临床指标对预测最关键"，是论文结果部分的重要图表。

**向 AI 提问的 Prompt：**

> 请帮我用 matplotlib 绘制随机森林模型的特征重要性水平条形图，要求：
>
> - 按重要性从高到低排序，最重要的特征在最顶部
> - 条形颜色根据重要性深浅渐变（越重要越深）
> - X 轴标签为"Feature Importance (Gini Impurity)"
> - 每条柱右侧标注具体数值（保留三位小数）
> - 尺寸 8×6 英寸，DPI 300，白色背景

**参考代码：**

python

```python
import pandas as pd
import numpy as np
import matplotlib.pyplot as plt
import matplotlib.cm as cm
from sklearn.ensemble import RandomForestClassifier

# （假设已完成数据准备，X 和 y 已定义）
model = RandomForestClassifier(n_estimators=100, random_state=42)
model.fit(X_train, y_train)

# 提取特征重要性并排序
feature_names = X_train.columns.tolist()
importances = model.feature_importances_
indices = np.argsort(importances)  # 从低到高排序（绘图时顶部最高）

# 颜色渐变：重要性越高，颜色越深
colors = cm.Blues(np.linspace(0.3, 0.9, len(importances)))
sorted_colors = colors[np.argsort(np.argsort(importances))]

fig, ax = plt.subplots(figsize=(8, 6), dpi=300)

bars = ax.barh(
    range(len(indices)),
    importances[indices],
    color=sorted_colors,
    edgecolor="white"
)

# 在每条柱右侧标注数值
for i, (bar, idx) in enumerate(zip(bars, indices)):
    ax.text(bar.get_width() + 0.002, bar.get_y() + bar.get_height() / 2,
            f"{importances[idx]:.3f}",
            va="center", ha="left", fontsize=9)

ax.set_yticks(range(len(indices)))
ax.set_yticklabels([feature_names[i] for i in indices], fontsize=10)
ax.set_xlabel("Feature Importance (Gini Impurity)", fontsize=11)
ax.set_title("Random Forest – Feature Importance\n(Heart Failure Dataset)",
             fontsize=12)
ax.spines[["top", "right"]].set_visible(False)

plt.tight_layout()
plt.savefig("feature_importance.png", dpi=300, bbox_inches="tight")
plt.show()
print("✅ 特征重要性图已保存")
```

### 3.2 科研 AI 绘图的通用方法论

#### 第一关：先搞清楚"这张图该用什么方式画"

科研绘图有两条完全不同的技术路线，选错了会让你在错误的方向上浪费大量时间：

| 路线                        | 代表工具                    | 核心原则                                  | 典型图表                                     |
| --------------------------- | --------------------------- | ----------------------------------------- | -------------------------------------------- |
| **代码生成**（数据驱动）    | Python + matplotlib/seaborn | 数值必须来自你的真实数据，AI 只负责写代码 | ROC 曲线、热力图、散点图、生存曲线、混淆矩阵 |
| **AI 直接生成**（概念驱动） | Gemini                      | 传达逻辑和视觉风格，不依赖精确数值        | 研究框架图、诊断流程图、解剖示意图、方法论图 |

> 判断方法很简单——如果这张图里的数字有我从数据集里算出来的，就必须用代码生成。

------

#### 第二关：写出让 AI 生成高质量绘图代码的 Prompt

同样是让 AI 写绘图代码，Prompt 质量的差距，可能决定你拿到"能跑但丑"的代码，还是"开箱即用的期刊级图表"。

**绘图 Prompt 的五要素：**

> **① 我的数据是什么形态**（别让 AI 猜） **② 我要画什么类型的图**（越具体越好） **③ 视觉规范要求**（颜色、字体、尺寸、DPI） **④ 内容标注要求**（数值标注、图例位置、参考线） **⑤ 输出要求**（包含示例数据、代码可直接运行）

**❌ 低质量 Prompt：**

> "帮我画一个 ROC 曲线"

**✅ 高质量 Prompt：**

> 你是一位精通医学数据可视化的数据科学家，熟悉 Nature/BMJ 期刊的图表规范。
>
> **① 数据形态**：我有一个二分类预测任务，已经用 scikit-learn 训练了三个模型，每个模型都能输出预测概率（`predict_proba`）和真实标签。
>
> **② 图表类型**：三条 ROC 曲线对比图，每条对应一个模型。
>
> **③ 视觉规范**：白色背景、无顶部和右侧边框（`spines` 隐藏）、色盲友好配色（蓝`#1f77b4`、橙`#ff7f0e`、绿`#2ca02c`）、线宽 2pt、尺寸 6×5 英寸、DPI 300。
>
> **④ 内容标注**：图例中直接标注 AUC 值，格式为`模型名 (AUC = 0.xxx)`；添加灰色虚线对角参考线；X/Y 轴标签用英文。
>
> **⑤ 输出要求**：请包含从零生成模拟数据的完整代码，确保直接运行即可看到图；在关键参数处添加中文注释。

------

#### 第三关：拿到代码之后，不要直接运行——先做这三件事

拿到 AI 生成的代码，一键运行，报错了又茫然。养成以下三个习惯，可以节省大量时间：

**① 先检查导入语句**

python

```python
# 看看 AI 用了哪些库，确认你已经安装
import matplotlib.pyplot as plt   # ← pip install matplotlib
import seaborn as sns             # ← pip install seaborn
from sklearn.metrics import roc_curve, auc  # ← pip install scikit-learn
```

只需扫一遍 `import` 行，没安装的先 `pip install`，再运行。

**② 把模拟数据替换成你的真实数据**

AI 生成的代码通常包含用 `make_classification()` 或随机数组生成的模拟数据，这只是为了让代码可以直接运行。你需要找到这部分，替换成你自己的 `X_train`、`y_test`、`y_score` 等变量。

python

```python
# AI 生成的模拟数据部分（找到它，替换掉）
X, y = make_classification(n_samples=300, ...)   # ← 删掉这块
X_train, X_test, y_train, y_test = train_test_split(...)  # ← 删掉这块

# 替换成你自己的数据
# y_test = df["DEATH_EVENT"]   （你的真实标签）
# y_score = model.predict_proba(X_test)[:, 1]  （你的真实预测概率）
```

**③ 先用小数据跑通，再用全量数据**

第一次运行时，在数据加载后加一行：

python

```python
df = df.sample(50, random_state=42)  # 先只用 50 行测试，跑通了再去掉这行
```

这样即使有问题，报错也会在几秒内出现，不会等了 5 分钟才发现有 bug。

------

#### 第四关：图跑出来了，但"不好看"——用 AI 迭代微调

第一版图表跑出来之后，通常需要至少 2～3 轮微调。**关键原则：在同一个对话里追问，不要重开。**

**常见微调需求 & 追问模板：**

| 问题             | 追问 Prompt                                                  |
| ---------------- | ------------------------------------------------------------ |
| 图例文字太小     | "请将图例字体改为 11pt，并在图例外加一个细边框"              |
| 标题和图之间太近 | "请在标题和图之间增加间距（`pad=20`）"                       |
| 中文显示为方框   | "中文显示乱码，请在代码开头添加设置中文字体的代码（系统是 Windows）" |
| 想换配色方案     | "请将配色改为 Nature 期刊风格：主色调为深蓝`#003f5c`、橙红`#bc5090`、金黄`#ffa600` |

------

#### 第五关：用 Gemini 生成概念性示意图（解决文字乱码问题）

当你需要的不是数据图表，而是**诊断流程图、方法论示意图**这类"概念性图片"时，推荐使用 Gemini）直接生成，而非写代码。

**通用 Prompt 框架（适合任何课题的框架图）：**

> 请生成一张科研方法论框架图，要求：
>
> **内容结构**：分为三个横向阶段——[阶段一名称]、[阶段二名称]、[阶段三名称]，每个阶段下方列出 2～3 个子模块，用中文标注。
>
> **视觉风格**：扁平化设计，白色背景，主色调为蓝色系，模块间用带箭头的连接线表示流程走向。
>
> **字体**：标题加粗，子模块使用正常字重，所有中文清晰可读。
>
> **尺寸**：横向宽幅（16:9 比例），适合插入 PPT 或论文。

**适合用 Gemini 生成 vs 必须用代码生成的图表对比：**

| 图表类型                 | 推荐方式        | 原因                                     |
| ------------------------ | --------------- | ---------------------------------------- |
| 研究框架图、技术路线图   | Gemini 直接生成 | 传达逻辑关系，不依赖精确数值             |
| 诊断流程图、决策树示意图 | Gemini 直接生成 | 需要文字标注 + 箭头逻辑，Gemini 渲染清晰 |
| ROC 曲线、混淆矩阵       | 必须用代码      | 数值来自真实数据，AI 无法生成正确数字    |
| 热力图、特征重要性图     | 必须用代码      | 同上                                     |

**不满意时，在同一对话里追问微调：**

> "图中左侧第一个模块的中文标注偏小，请放大字号并加粗"
>
> "三个阶段之间的箭头改为双向箭头，表示双向影响关系"
>
> "整体色调太深，请改用更浅的蓝色系，背景保持白色"

### 3.3 学术公式排版：让 AI 写出标准 LaTeX 代码

#### 为什么不能直接复制 Word 里的公式？

医学 AI 论文提交给期刊（或用 Overleaf 写论文）时，**公式必须用 LaTeX 代码编写**，而不是 Word 里的"插入公式"对象。两者格式完全不兼容。

#### 以 F1 Score 为例：

F1  Score 是评估实体抽取、分类模型时最重要的综合性指标（综合考量查准率和查全率），其计算公式为：
$$
F_1 = \frac{2 \times \text{Precision} \times \text{Recall}}{\text{Precision} + \text{Recall}}
$$
**向 AI 提问的 Prompt：**

> 请帮我写出以下公式的标准 LaTeX 代码，要求：
>
> 1. F1 Score 的计算公式（含 Precision 和 Recall 的定义展开）
> 2. 公式编号为 (1)
> 3. 适合粘贴进 Overleaf（使用 `equation` 环境）
> 4. 同时给出可以在 Typora / Markdown 文件中预览的行内版本

**AI 给出的 LaTeX 代码：**

latex

```latex
% ── 粘贴进 Overleaf 的完整公式（带编号）──────────────────
\begin{equation}
    F_1 = \frac{2 \times \text{Precision} \times \text{Recall}}
               {\text{Precision} + \text{Recall}}
    \label{eq:f1_score}
\end{equation}

% 展开版（含 TP / FP / FN 定义）
\begin{equation}
    F_1 = \frac{2 \cdot TP}{2 \cdot TP + FP + FN}
    \label{eq:f1_expanded}
\end{equation}

% 引用公式时使用（在正文中写）：
% As shown in Equation~\ref{eq:f1_score}, ...
% ── 粘贴进 Typora / Markdown 的行内版本 ──────────────────
$$
F_1 = \frac{2 \times \text{Precision} \times \text{Recall}}{\text{Precision} + \text{Recall}}
$$
```

#### 让 AI 帮你检查 LaTeX 语法

写好公式后，可以把代码发给 AI 进行检查：

> "请检查以下 LaTeX 代码是否有语法错误，并告诉我在 Overleaf 编译时是否需要引入额外的宏包：
>
> latex
>
> ~~~latex
> [粘贴你的代码]
> ```"
> ~~~

**常用需要在 Overleaf 引入的宏包（粘贴到导言区）：**

latex

```latex
\usepackage{amsmath}   % 支持高级数学公式环境
\usepackage{amssymb}   % 支持额外数学符号
\usepackage{booktabs}  % 专业三线表格（投稿必备）
\usepackage{graphicx}  % 支持插入图片
```

### 3.4 AI 幻觉的识别与防范

> **在医疗科研场景中，幻觉不只是技术缺陷，可能是临床风险。** 本节聚焦于科研过程中最常遇到的几类幻觉。

#### 幻觉类型速查

| 幻觉类型     | 具体表现                               | 高危场景                       | 防范方法                                      |
| :----------- | -------------------------------------- | ------------------------------ | --------------------------------------------- |
| **文献幻觉** | 捏造论文标题、作者、期刊名             | 让 AI 推荐参考文献             | 每条文献必须在 PubMed/Google Scholar 逐一核实 |
| **数值幻觉** | 给出"看起来合理"但并非你真实数据的数字 | 让 AI 直接生成图表（非代码）   | 所有图表必须由 Python 代码基于真实数据生成    |
| **图文幻觉** | 图表中文字变乱码、数值标注错误         | 用图像生成模型绘制含数据的图表 | 改用 Gemini Nano Banana（高保真文字渲染）     |
| **概念幻觉** | 混淆相似的临床术语或统计概念           | 解释机制、定义术语             | 用 NotebookLM 绑定文献来源，锚定回答至原文    |

#### 使用 NotebookLM 从源头消灭文献幻觉

> 💡 **NotebookLM 的核心价值**：与 ChatGPT/Claude 的"通用知识库"不同，NotebookLM 只从**你上传的文献**中回答问题。如果资料里没有，它会直接说"这份资料中未提及"，而不是编造一个听起来合理的答案。每条回答后都有精确到原文段落的来源标注，可点击直接跳转核查。

**科研文献管理工作流：**

1. 在 **https://notebooklm.google.com/** 创建一个新笔记本（如"心衰预测研究"）。

2. 上传你的核心参考文献（支持 PDF、Word、网页 URL、Google Docs）。

3. 设定 AI 角色（点击右上角对话设置）：

   > "你是一位严格的医学统计审稿人。针对我的每个问题，先给出结论，再列出 2-3 个来自上传文献的支撑证据，最后指出该结论在现有资料中最薄弱的地方。所有回答必须有来源标注。"

4. 直接提问，所有回答都锚定在你的文献范围内，**不会自由发挥**。
